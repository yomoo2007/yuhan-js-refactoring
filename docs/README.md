## 코드를 읽는 순서

1. `index.html`과 `js/main/main.js`에서 게임 선택 흐름을 확인합니다.
2. `tft.html`에서 스크립트 실행 순서와 화면 ID를 확인합니다.
3. `tft-api.js` → `tft-model.js` → `tft.js` 순서로 조회·변환·표시를 읽습니다.
4. 공통 UI는 `js/shared/`, TFT 보조 화면은 `js/tft/`, 서버는 `js/server/`에서 찾습니다.

## 데이터와 캐시 위치

- `data/tft/`: 프로젝트에 포함하는 세트 17 정적 메타데이터입니다. 현재 화면의 스크립트 실행 순서를 유지하도록 JavaScript 형식으로 제공합니다.
- `js/tft/`: API 호출, 데이터 정규화, 화면 렌더링과 샘플 생성 등 실행 로직입니다.
- `assets/`: 이미지·영상 등 화면 자산입니다.
- `.tft-cache/`: 서버가 실행 중 생성하는 Riot 응답·아이템 집계 캐시입니다. Git 추적과 정적 파일 제공에서 제외됩니다.

## 주석 작성 기준

- 파일 첫 주석에 역할과 개별 문서 경로를 적습니다.
- 주요 함수에는 목적, 입력·반환값의 특이점, 취소·재시도·중복 제거 이유를 한국어로 설명합니다.
- API 경로, ID, 변수명과 외부 데이터 키는 코드 연결을 유지하도록 원문을 사용합니다.
- 자동 생성 데이터는 값마다 주석을 넣지 않고 파일 역할과 사용처를 문서화합니다.
- 파일의 함수·공개 API·DOM ID를 바꾸면 해당 개별 문서와 dialog 가이드도 함께 갱신합니다.
