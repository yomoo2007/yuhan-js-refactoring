# 로컬 실행과 API 사용법

[문서 목차](README.md) · [서버 파일 목록](FILES.md#서버와-로컬-실행)

## 실행

Node.js 20 이상을 준비하고 프로젝트의 `start-local.bat`를 더블 클릭합니다. 실행기는 서버가 이미 준비되어 있으면 재사용하고 기본 브라우저에서 `http://localhost:5174/index.html`을 엽니다.

터미널에서 직접 실행하려면 프로젝트 폴더에서 다음 명령을 사용합니다.

```powershell
node assets/js/server/server.js
```

포트 변경은 서버 실행 전에 `TFT_PORT` 환경 변수를 지정합니다. 다른 포트를 사용하면 브라우저 주소도 그 포트로 접속해야 합니다. 서버는 `127.0.0.1`에 바인딩합니다.

## 로컬에서도 실제 API가 동작하나요?

TFT 전적 검색은 LoL과 같이 브라우저에서 개인 서버 `http://prestigelulu.com:3000`에 요청합니다. 해당 서버는 브라우저가 전달한 키로 Riot에 요청합니다. 유효한 키와 개인 서버 연결이 필요합니다. TFT 이미지 메타데이터는 로컬 서버를 사용합니다.

| 실행 방법 | 화면 | 실제 Riot 검색 |
| --- | --- | --- |
| `start-local.bat` 또는 Node 서버의 주소 | 메인·LoL·TFT | 유효한 게임별 키가 있으면 가능 |
| 일반 Live Server 또는 HTML 직접 열기 | 정적 화면 확인용 | 이 프로젝트의 API 프록시가 없어 직접 사용 불가 |

## 키 설정

`assets/js/server/config.example.js`를 같은 폴더의 `config.js`로 복사하고 다음 두 항목을 입력합니다.

```js
module.exports = {
  TFT_API_KEY: "발급받은 TFT 키",
  LOL_API_KEY: "발급받은 LoL 키",
};
```

키를 바꾼 후 기존 Node 서버를 종료하고 다시 실행합니다. 실행기가 준비된 서버를 재사용하면 설정 변경이 자동 반영되지 않습니다. `config.js`는 Git과 정적 제공에서 제외되며 실제 키를 README나 프런트엔드 코드에 넣지 않습니다.

## 연결 확인과 오류

- `http://localhost:5174/api/tft/status`의 `configured`는 서버가 읽은 TFT 키의 존재 여부입니다. LoL 키 유무나 두 키의 유효기간을 검증한 결과는 아닙니다.
- 상태 응답의 `projectId`는 실제 프로젝트 폴더의 식별값입니다. 실행기는 같은 값인 서버만 재사용하며, 이 항목이 없는 이전 서버는 재시작해야 합니다.
- 실제 검색에서 401·403이 발생하면 키 인증·만료·권한을 확인합니다.
- 429는 Riot 요청 한도 응답입니다. 안내된 시간 후 다시 시도합니다.
- 503은 해당 게임의 키가 설정되지 않은 경우입니다.
- 일반 정적 서버에서 JSON 대신 HTML이 반환되면 `start-local.bat`로 실행한 주소인지 확인합니다.
- 실행기 로그는 `.tft-preview.log`, 오류 로그는 `.tft-preview-error.log`입니다.

현재 LoL은 계정·소환사 프로필 조회까지 연결되어 있습니다. TFT는 세트 17 전적·랭크·통계를 표시하며 API 키가 없어도 샘플 화면을 볼 수 있습니다.

## 데이터·이미지·캐시 구분

| 경로 | 역할 |
| --- | --- |
| `data/tft/` | 프로젝트에 포함하는 세트 17 정적 메타데이터 |
| `assets/` | 실제 이미지·영상 |
| `.tft-cache/` | Riot 응답 캐시·수집 아이템 집계. 실행 중 서버가 생성 |
| 브라우저 Service Worker 캐시 | TFT 이미지·정적 메타데이터 재사용 |

세트 데이터와 이미지 이름을 바꾸면 참조 경로 및 `tft-sw.js`의 캐시 버전도 함께 갱신합니다. 서버 응답 캐시와 브라우저 자산 캐시는 별도입니다. [에셋 안내](ASSETS.md)를 참고하세요.
